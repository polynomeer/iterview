Spring의 @Transactional은 프록시 기반 AOP로 동작합니다. 외부에서 빈을 호출하면 프록시가 트랜잭션을 시작하지만, 같은 클래스 내부에서 this.method()로 호출하면 프록시를 거치지 않기 때문에 어드바이스가 적용되지 않습니다.

정산 시스템을 재구축할 때 배치 내부에서 건별 저장 메서드를 self 호출해서 한 건 실패 시 전체가 롤백되지 않는 문제가 있었고, 그래서 구조를 분리해서 해결했습니다.

개선 포인트 — 결과 (기존 /answer-attempts/:id/result + /interviews/:id/result 결과 화면 패턴 통일)

  1. 총점 + 변화량 + 상태 단어. 이전 시도 대비 Δ를 항상 표시(“what improved after the last retry?” 질문에 답).
  2. 다음 행동이 결과 옆에. 가장 약한 항목을 한 문장으로 짚고 “다시 답하기”를 주 행동으로. 복습 예약은 자동화하고 알림만.
  3. 답변 본문에 직접 하이라이트. 별도 카드로 흩어진 피드백 대신, 문장 단위로 좋은/보완 부분 표시. 오류 시에는 백엔드 원문(“Answer attempt not found: 1”) 대신 사용자 문장 + 복구 링크.
